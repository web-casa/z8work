# 原生格式扩展第二步：BMP、TGA、QOI

日期：2026-09-13。承接 [第一步能力盘点](FORMAT_EXPANSION_PHASE1.md)。

## 本阶段范围

新增 BMP、TGA、QOI 输入，以及图片和 PDF 页面输出到这三种格式。产品范围为 23 个输入扩展名、13 个输出格式、129 条路线（原有 84 条 + 新增 45 条）。这不是全部文件格式之间的任意互转；音频、文档的范围保持现有定义。

| 输出 | 行为                  | 限制                                          |
| ---- | --------------------- | --------------------------------------------- |
| BMP  | BMP3、白底、8 位 sRGB | 不保留透明度和元数据/ICC；通常较大            |
| TGA  | 8 位 sRGB、保留 alpha | 不保留元数据/ICC；不保证比输入小              |
| QOI  | 8 位 sRGB、保留 alpha | 不保留元数据/ICC；无损仅针对量化后的 8 位像素 |

输入先自动纠正方向，应用嵌入的 ICC 转换至标准 sRGB，再移除配置并输出。宽色域、16 位输入到这些格式并非无损保真。静态图片仍只处理首帧；PDF 按原有分辨率、200 页和尺寸限制逐页导出。GIF 动画、ICO 多尺寸、TIFF 多页、JPEG XL、RAW、SVG 留待后续独立验收。

格式选择依据：[ImageMagick 官方格式表](https://imagemagick.org/formats/)明确列出 BMP/TGA/QOI 的读写能力；[QOI 规范](https://qoiformat.org/qoi-specification.pdf)定义其 RGB/RGBA 像素表示。本次以实际包内转换结果为验收依据，未把官方格式表直接当作已支持列表。

## 实现及 review 修正

- 复用共享范围清单，更新 Rust 输出枚举、显式输入/输出 coder、安全策略和前端格式契约。Linux 包补入 BMP/TGA/QOI 模块，不开放全部 coder 或外部 delegates。
- 在既有文件头/解码校验中加入 BMP3、QOI 和 TGA。TGA 无独立 magic 前缀，先检查输出结构，再通过引擎解码；头部检查本身不等于有效图片。
- 新格式先使用随程序编译的标准 sRGB 配置变换颜色，再去掉元数据。初次实测发现白名单拒绝读取 ICC，修正为只读 ICC 权限；配置文件由程序写入私有工作目录，使用相对文件参数兼容 Windows。
- 新格式隐藏不适用的质量和元数据开关，保留 PDF 分辨率选择；界面和双语结果说明披露白底、透明度、位深与配置丢弃行为。
- Review 找到批量格式下拉框和前端预览识别仍重复维护列表，已接入共同范围；同步商店草稿及静态说明页，避免格式清单落后于源码。修正预览识别把没有扩展名的 `bmp` 或隐藏文件 `.bmp` 当作图片的问题。
- 新增独立真实文件验收命令 `bundle-check ENGINE_DIRECTORY --image-expansion`，以及浏览器交互脚本 `bun run desktop:test:image-expansion`。前者走生产转换/预览路径；后者使用官方 Tauri IPC mock，只证明 WebView 交互，不代替系统对话框或原生 GUI 验收。

## 验证

本机开发引擎验证通过：45 条新增路线（含三种 PDF 三页输出）、9 项质量档位一致性检查、18 项 ICC/16 位/EXIF 方向检查，另有三种输入各自的预览、取消和损坏文件拒绝检查。比较真实再解码像素、alpha、尺寸，并核对 PDF 页面顺序。

本机脚本测试 196 项通过，Rust 测试 119 项通过、3 项按既有规则忽略；前端检查 0 errors / 0 warnings。浏览器三种格式的预览入口、选项隐藏和切换回 JPEG 已通过；截图为人工构造任务，不含真实用户文件。

完整质量验收也已更新：原有 84 条基础结果和 `imageExpansion` 内的 45 条结果合并后，逐条对照共享范围核对唯一性。当前 `validateQuality` 要求同时具备新增格式报告，不能用历史 84 条报告代替新范围验收。本机完整回归还通过 20 项质量检查、240 项图片校准与缺 Pandoc 的隔离检查。

Review/CI 曾发现两处旧范围假设：质量检查按新范围核对，却未合并新增结果；开发环境缺 Pandoc 检查把图片输出数量写死为 4。两者已修正。第一轮 Linux 构建 `34761035844` 双架构均在前者处失败，不能作为打包成功证据。
