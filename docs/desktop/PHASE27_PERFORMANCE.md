# Phase 27：性能预算与已测范围

日期：2026-09-09。首版产品功能与 84 条基础质量路线已验证，**正式性能验收尚未全部关闭**。此表沿用 [R1 固定场景](PHASE24_READINESS.md#性能与资源测量计划)，分开列出本机实测和 R6 必补项，不将开发机数据套用于 Windows、macOS 或 strict Snap。

## 测量条件

Debian 13 / Linux ARM64，内核 `7.0.14-orbstack-00380-ga7e0a2dc9535`，16 个虚拟 CPU（供应商字段 Apple，具体物理型号未报告）、约 23.5 GiB 可见内存。磁盘为虚拟块设备，未验证实际介质。Rust 1.96.0 debug 开发程序、Node 24.18.0、系统 WebKit；引擎版本与摘要随格式报告/输入收据记录。它不是优化后的发行包、空闲独占机器或 OS 冷缓存实验。

资源监督器每 100 ms 查询 `/proc`，对当时可见的子孙进程 RSS 求和，包含启动器、WebView、引擎等；共享页可能重复计数，短暂峰值可能漏采，已脱离父子关系的系统服务不在此范围内。不能解释成 PSS、独占物理内存或目标平台的峰值内存承诺。报告包含采样耗时和监督器 CPU 时间。

这些警戒线用于同类 Linux ARM64 开发环境复跑后人工比较，不修改运行时期限、质量或资源限制；超出时须调查，不能通过降低输出质量让它通过。所有目标发行预算仍必须在确切候选上重测。

计时从 WebDriver 创建会话请求开始，到语言选择与选择文件控件可用；因此包含驱动开销，不是精确进程入口或合成器首帧时间。60 次均使用已有配置并重启进程，未清除 OS 缓存。阻塞场景要求可交互时 ImageMagick 仍在准备，之后允许按已有 10 秒探测期限失败；其余引擎必须独立就绪。未把“所有引擎就绪”与“窗口可操作”混为一个指标。首次配置启动的完整重复计时仍未执行。

| 固定场景                 | 本轮执行                                                                              | 尚未执行 / 关闭要求                                                                                         |

以上缺项不改变 84 条基础样本的通过结论，但**阻止填写完整性能验收通过**。未测试场景没有填入猜测的时间或内存数字。
