# Phase 1 补充开发与 review

日期：2026-09-08。延续 [Phase 1 / M1 实施](PHASE1_IMPLEMENTATION.md)，本次补齐文件授权失效、取消边界与历史锁释放的处理。

## 发现与修复

| 问题                                                   | 用户影响                                                   | 修复和回归验证                                                                                                                                              |
| ------------------------------------------------------ | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 输出目录读取元信息失败时没有撤销授权                   | 目录已删除，界面仍允许使用旧授权重试                       | 用明确的输入/输出错误类型代替错误文字前缀判断；目录消失后撤销输出授权，重新选择后可转换。测试先复现失败，再验证修复                                         |
| 文件打开操作发生在队列状态锁内，且打开特殊文件可能阻塞 | 输入被替换为命名管道时，转换、查看状态、取消和退出可能卡住 | 共享普通文件打开函数；打开前及取得句柄后核查类型，Unix 使用非阻塞打开；转换前的文件检查移到状态锁外。实际命名管道分别验证新增导入与已登记文件被替换两种入口 |
| 移出状态锁后，取消可能发生在引擎启动之前               | 已取消的任务仍可能进入执行器                               | 检查文件后、调用执行器前再次检查取消；在运行通知边界触发取消，断言执行器调用次数为零                                                                        |
| 仅关闭锁文件句柄，锁可能被副本短暂保留                 | 关闭后重新打开历史时偶发“记录正在使用”                     | 测试中发现重开失败；用复制句柄稳定复现。队列析构先停止并等待工作线程，再显式解锁；仍保留运行中的独占锁                                                      |

新增五个回归测试，另修正已有取消测试的同步条件：需要验证“运行中取消”时，等待执行器确实启动，避免把已设置 `running` 误当作引擎已经执行。

输入删除后即使同名文件重新出现，也需要再次通过原生选择器授权。输出目录失效不会撤销无关输入的授权；重新选择目录后可以重试。这些状态仍由 Rust 队列统一决定。

Unix 非阻塞打开使用标准库 [OpenOptionsExt::custom_flags](https://doc.rust-lang.org/std/os/unix/fs/trait.OpenOptionsExt.html#tymethod.custom_flags)，`libc` 仅作为 Unix 条件依赖，沿用锁文件中已有版本；显式解锁使用 [File::unlock](https://doc.rust-lang.org/std/fs/struct.File.html#method.unlock)。

## 验证

本机为 Linux ARM64。开发 feature 的 Rust 测试 29 项通过，默认 feature 的测试 30 项通过；均另有一个由进程测试调用的 ignored fixture。Clippy、Rust 格式检查、桌面构建、桌面类型检查（0 错误、0 警告）、前端同步与契约测试 7 项及桌面 ESLint 均通过。

重新构建桌面程序后，真实原生转换验证 9 个样本，以及 Rust 队列独立执行 3 项任务、防重复和历史恢复。原生 GUI 验证文件/目录选择、两个 PNG→AVIF 任务在窗口刷新后继续执行、结果恢复、防重复提交、第二实例退出、未授权 IPC 拒绝、运行中清空及保留已保存文件，脚本退出码为 0。GUI 使用 GTK 文件选择器；测试环境的 document portal 挂载警告不构成 strict Snap portal 验收通过。

## 仍需后续验证

- 本次不改变正式包与商店验收状态：Windows/macOS、MSIX、strict Snap 和自包含引擎仍未在本机完成验证。
- Unix 命名管道保护不等于所有文件系统操作都有超时；网络盘上的元信息查询/读取、历史写入仍可能阻塞，退出仍需等待正在执行的文件系统调用。
- 已打开句柄和元信息核对不能完全阻止外部程序并发改写内容或替换输出目录。本次不声称提供完整 OS 沙箱。
- 强杀主程序后的全部子进程回收、崩溃遗留临时目录清理和掉电持久性仍按后续阶段处理。
