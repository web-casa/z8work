# Phase 1 / M1 平台适配层：实现与 review

后续授权与退出边界修复、最新测试结果见 [补充开发与 review](PHASE1_FOLLOWUP_REVIEW.md)。本文保留首轮实现与验证记录。

日期：2026-09-08。本轮将用户所称的 Phase 1 对应到 [V1 方案](V1_PLAN.md) 的 M1 平台适配层，在 M0 原型上实现 Rust 队列、状态同步、历史恢复与单实例。本地环境为 Debian 13 / Linux ARM64；当前工作区尚未提交或推送。

**平台适配层初版已实现并通过本机验证。** M0 尚未完成的自包含引擎、MSIX、strict Snap 和 macOS 安装验证继续保留为待完成项，本轮不会把开发机结果扩展成跨平台或商店验收通过。转换格式与原型限制沿用 [M0 记录](M0_IMPLEMENTATION.md)。

## 1. 本轮交付

| 模块             | 实现                                                                                                                        |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Rust 队列        | 一个后台调度线程依次执行完整批次；前端不再循环调用单文件转换                                                                |
| 共享任务契约     | schema、队列 epoch、单调 revision、任务 ID、attempt、状态、授权、结果和错误；Rust/TypeScript 通过共同 JSON fixture 检查契约 |
| 界面同步         | 先订阅变更通知，再读取快照；合并密集通知，拒绝旧快照，卸载时释放监听，5 秒补充同步与窗口聚焦同步                            |
| 幂等提交         | UUID 请求标识 + epoch + 任务预期轮次；同一请求重发返回当前状态，不重复编码；相同标识不同参数、旧轮次或已清空队列的请求被拒  |
| 取消、移除、清空 | 支持单项/整批取消；移除运行项时等待其清理结束；移除排队项无需等待不相关的运行项；保留原件及已保存结果                       |
| 正常退出         | 窗口关闭与应用退出均取消队列，等待运行任务和进程清理后退出                                                                  |
| 历史记录         | 限量 JSON 原子替换；恢复任务与保存结果记录，运行/排队中的历史任务标记 interrupted，不自动恢复执行                           |
| 原生文件授权     | 文件选择器登记输入；重启后撤销旧授权，需重新选择输入与输出目录；开始执行前复核文件信息，并把已打开的文件句柄交给转换层      |
| 单实例           | 第二个实例退出并请求聚焦主窗口；历史文件再加独占锁，防止不同桌面会话同时写同一份记录                                        |
| 操作界面         | 显示排队/转换/成功/失败/取消/中断、轮次、旧结果、重新授权、重试与移除；保存目录默认定位到当前已选目录或输入文件目录         |

没有百分比数据时显示真实任务阶段，不制造进度百分比。这里的事件是带版本的变更通知，随后读取权威快照；不是完整的任务增量补丁协议。队列上限 100 项，这种实现便于避免订阅与快照交接时丢失状态，后续扩大队列时再评估增量传输。

## 2. 关键实现位置

- [队列与调度器](../../src-tauri/native/src/queue/mod.rs)：登记、提交、防重复、取消/清空、关闭和执行结果。
- [任务契约与文件标识](../../src-tauri/native/src/queue/model.rs)、[记录持久化](../../src-tauri/native/src/queue/store.rs)：限制、原子写入和恢复规则。
- [原生转换层](../../src-tauri/native/src/convert.rs)：接受已经打开的输入句柄，复制期间复核变化，继续使用原有引擎验证与防覆盖保存。
- [Tauri 入口](../../src-tauri/src/main.rs)、[能力声明](../../src-tauri/capabilities/main.json)：原生选择器、后台命令、单实例、正常退出和主窗口权限。
- [前端契约](../../desktop/src/platform/queue-contract.ts)、[同步适配](../../desktop/src/platform/queue-sync.ts)、[Tauri 传输](../../desktop/src/platform/tauri.ts)、[工作区](../../desktop/src/App.svelte)：平台调用集中管理，界面依据快照展示。

单实例采用 [Tauri 官方插件](https://v2.tauri.app/plugin/single-instance/)，在建立队列和读取历史前注册。其 Linux 路线依赖 D-Bus，因此 Snap 打包时仍须按最终应用标识配置对应权限。历史独占锁使用 [Rust File::try_lock](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock)，不能把同一 D-Bus 会话内的验证当成全部安装环境已通过。

主窗口授权九个自定义命令及事件监听/取消监听；旧 `convert_file` 和通用文件读写/事件发送不在可用权限中。Rust 发送状态通知使用 [Tauri 事件接口](https://v2.tauri.app/develop/calling-frontend/)。事件只用于通知刷新，任务事实仍以 Rust 快照为准。

## 3. 恢复与保存规则

历史文件位于 Tauri `app_data_dir()/queue-v1.json`，旁边的 `queue-v1.lock` 用于独占锁。开发身份仍保留 `work.z8.desktop.m0`，避免因为阶段命名变更无意换掉数据目录；正式发行身份须在打包阶段统一。

记录包含任务名称、大小、格式、轮次、状态、结果路径、错误和提交标识；不保存输入正文，也不把原输入绝对路径持久化为可执行授权。输出目录提示可以恢复，但输出授权不会恢复。重新选择文件由用户明确操作，不自动扫描浏览器、磁盘或历史路径。

- 界面刷新：Rust 继续运行；重新挂载后按 revision 恢复当前任务。
- 应用重启：已保存结果作为历史显示；中断任务提示用户先检查输出目录，再重新选择文件与目录、明确重试。
- 保存输出与记录之间崩溃：文件可能已经落盘，但记录仍显示中断。二者不具备跨文件系统事务；提示不假定任务失败后没有结果，重试仍使用防覆盖命名。
- 记录写入失败：保留内存中的结果和已生成文件，暂停后续任务，展示错误并提供重试保存。清空仍可用于缩小超限记录；不会因记录超限陷入“无法保存也无法清空”。
- 损坏或未知版本记录：拒绝覆盖原记录，界面显示错误；先保留备份再排查，不能静默清空或启用其中的路径。

记录大小上限 2 MiB、最多 100 项、最多 1024 个批次请求；清空全部任务更换 epoch 并释放请求历史。默认不因额度满而删除用户已有的保存结果。

## 4. Review 中发现并修复的问题

| 问题                                                  | 修正与验证                                                                              |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 前端循环控制任务，刷新后丢失剩余批次                  | 改为 Rust 调度；真实窗口在提交后刷新，两个 AVIF 任务继续执行并恢复显示                  |
| 重复点击/响应丢失可能重复编码                         | 持久化提交标识，并核查 epoch 和 attempt；重复请求、参数冲突、旧轮次及清空后重放测试通过 |
| 历史路径可能被错误当成授权                            | 重启恢复状态但撤销输入/输出授权；原输入不持久化为可执行路径；替换输入被拒并要求重新选择 |
| 事件订阅与快照存在交接窗口                            | 先订阅、后读快照；变更期间再次同步，旧响应不能覆盖新 revision，延迟订阅也能正确释放     |
| 转换成功但历史保存失败时可能丢失成功事实              | 保留 saved 状态与结果路径，暂停后续任务；模拟写入失败后恢复继续执行通过                 |
| 历史超限时“重试保存”和“清空”互相阻塞                  | 允许在记录保存错误状态下取消/清空，删减后的记录重新提交；超过 2 MiB 的故障测试通过      |
| 移除排队项误等当前其他任务                            | 仅等待被移除的运行任务；针对性测试通过                                                  |
| 不同会话可能同时修改同一历史文件                      | 除单实例插件外增加独占文件锁，第二个队列实例不能写相同记录                              |
| 只处理窗口关闭可能漏掉应用退出                        | 两类退出都进入同一队列停止流程，禁止后续任务启动；跨平台 OS 菜单退出仍需各端实测        |
| 保存目录初始定位不便，自动化也易进入 GTK 最近文件搜索 | 默认定位到已选输出或输入目录，保留原生确认步骤；实际 GTK 文件与目录选择通过             |
| 测试退出时的清理失败可能被吞掉                        | 清理错误写入日志并使测试返回非零，不把残留任务当作验证成功                              |

## 6. 运行与复现

沿用 [M0 的开发引擎准备方法](M0_IMPLEMENTATION.md)，设置 `Z8_DEV_ENGINE_MANIFEST`。有桌面会话时运行 `bun run desktop:dev`。常用检查：

```sh
bun run desktop:check
bun run desktop:build
bun run desktop:test
bun run desktop:test:ui
bun run desktop:smoke
cargo test --locked --manifest-path src-tauri/Cargo.toml -p z8-native --no-default-features
cargo clippy --locked --manifest-path src-tauri/Cargo.toml --workspace --all-targets --features development-engines,custom-protocol -- -D warnings
```

Linux 完整 GUI 检查需要 `tauri-driver`、`WebKitWebDriver`、Xvfb、D-Bus 和 xdotool。先构建，设置 `Z8_XDOTOOL` 为实际工具的绝对路径，再执行：

```sh
cargo build --locked --manifest-path src-tauri/Cargo.toml --features development-engines,custom-protocol
xvfb-run -a --server-args='-screen 0 1280x900x24' \
  dbus-run-session -- bun run desktop:test:gui
```

若使用此次解压到 `/tmp/z8-m0-deps` 的 xdotool，还需将 `Z8_XDOTOOL_LIBRARY_DIR` 指向实际配套库目录。这些临时开发依赖不是发行依赖布局。脚本使用独立数据目录、动态本地端口和自建 WebDriver，会保存证据并关闭自己的进程。基础窗口、语言和 IPC 检查仍可使用 `bun run desktop:gui:smoke`，该命令需要事先启动 WebDriver，见 M0 说明。

## 7. 明确保留的边界

本轮验证正常取消、清空、退出流程及中断历史恢复。强杀主程序后的所有子进程回收、遗留临时目录扫描、系统更新/休眠中断、磁盘掉电、恶意并发改写与输出目录替换竞态仍需进一步验收；打开文件句柄与元信息复核不能代替完整 OS 沙箱。

格式保真、完整多页 PDF、缩略图与预览、系统文件关联/拖放、分引擎可用性降级、自包含依赖和商店安装继续按 V1 后续阶段处理。现有图片/文档转换限制没有因更换队列自动消失。下一阶段应补齐 M0 安装与引擎分发门禁，再扩大 M2 的格式和交互范围。
