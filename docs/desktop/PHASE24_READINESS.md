# Phase 24：首版矩阵、平台条件与风险清单

日期：2026-09-09。范围：R1 清点与源码契约，未执行商店提交或三端安装验收。能力定义见 [v1-scope.json](../../packaging/desktop/v1-scope.json)，最终验收仍按[七阶段方案](REMAINING_V1_PLAN.md)。

## 能力与验收归属

| 类别 | 输入扩展                                   | 输出                  | 引擎             | 声明路线数 | 样本与缺项                                                                      |
| ---- | ------------------------------------------ | --------------------- | ---------------- | ---------- | ------------------------------------------------------------------------------- |
| 图片 | png/jpg/jpeg/webp/avif/heic/heif           | png/jpeg/webp/avif    | magick           | 28         | HEIC seed、透明图、渐变、质量预设生成器已有；jpeg/heif 别名及保真样本在 R4 补齐 |
| PDF  | pdf                                        | png/jpeg/webp/avif    | mutool + magick  | 4          | 已有生成式多页/超限/部分成功测试；字体保真及目标包 R4/R6 验收                   |
| 媒体 | mp3/wav/flac/ogg/m4a/opus/mp4/mov/mkv/webm | wav/mp3/flac/opus/m4a | ffmpeg + ffprobe | 50         | seed 音频与生成式视频/音频样本；容器扩展不代表所有 codec 均支持                 |
| 文档 | md/docx                                    | txt                   | pandoc           | 2          | Markdown 生成器和仓库 DOCX，验证中文及正文；不保留排版                          |

合计 20 个输入扩展、84 条声明路线，包含同格式输出与别名。Rust 测试对每条声明路线执行实际 `output_formats`/`formats_for`，同时移除每个所需引擎，验证该路线被禁用。测试不启动编码器，**84 不是真实转换或安装验收通过数量**，也不穷举所有可能的新输入扩展。前端测试验证输出类型、语言偏好、产物身份及样本引用。

每组 JSON 关联实现和样本/生成器路径。语言为简体中文、英文及跟随系统；产物为 Windows x64 MSIX、Linux AMD64 strict Snap、macOS ARM64 本地 app、Linux ARM64 本地回归包。R1 关闭契约核对，R4 关闭样本质量，R6 关闭确切安装包验证。

当前预算人工对照源码记录在 JSON：输入 512 MiB、队列/单次导入 100 项、PDF 输入 100 MiB/200 页/单边 4000 像素，预览输入 32 MiB/输出 512 KiB/单边 256 像素。预算字段不是新的运行时配置，不能只改 JSON 就改变限制；本轮测试核对字段与源码引用合法性，没有重新执行全部预算边界用例。

平台执行入口复用既有工具：

- Snap：`desktop:snap:installed --preflight --output NEW_DIR`，随后按 [Phase 9](PHASE9_IMPLEMENTATION.md)准备已安装候选与授权测试。本轮命令从仓库根目录执行；NEW_DIR 必须不存在。
- Windows：按 [Phase 14](PHASE14_IMPLEMENTATION.md)使用 `desktop:msix:acceptance`；其默认输入校验不能算签名或安装，实际执行所需参数以脚本和该阶段说明为准。
- macOS：R5 补原生引擎布局与本地 app 构建入口；目前没有 `packaging/desktop/macos`，不得编造已经可用的打包命令。

当前没有已分配的远程平台执行人或已验证连接入口。上述条件由 R1 提前列出，R5/R6 继续追踪；可以继续 R2，不能据此关闭后续平台验收。

## 性能与资源测量计划

这些是 R1 固定的测量方法；没有在本轮跑性能压测，阈值由 R4 基于各目标设备证据冻结。每份报告必须记录源码、候选/样本 SHA-256、生成器版本、系统/架构、CPU/内存、磁盘类型、引擎版本、设置及测试次数；不把开发机数据套用于其他目标。

| 场景           | 样本和次数                                                                  | 指标与后续断言                                                                                      |
| -------------- | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 启动与引擎就绪 | 正常、探测阻塞、单引擎失败，各 20 次；区分首次配置与已有配置启动            | 单调时钟测进程启动→可交互首屏、各引擎就绪；阻塞探测释放前首屏须可操作。进程重启不叫“操作系统冷缓存” |
| 图片压缩       | 固定透明图、16 位渐变、HEIC seed 与 R4 冻结的照片样本，每路线/质量预设 5 次 | 转换和发布分别耗时，报中位数/最大值、输出体积/像素/保真；不假定 AVIF 总比 WebP 小                   |
| PDF            | 固定三页、200 页、201 页及高像素页生成器，每场景 5 次                       | 首个成功页/总耗时、峰值工作目录、取消后已保存页；201 页按预算拒绝                                   |
| 音频与视频提取 | 固定 seed 与明确容器/codec、短/长时长生成器，每场景 5 次                    | 阶段/百分比与实际时长、声道，记录转换时间和峰值内存；未知时长不能伪造进度                           |
| 队列与取消     | 1 项、100 项、101 项导入；编码和保存各阶段取消 20 次                        | 101 项按已有策略拒绝；取消请求→引擎树及工作目录释放的耗时；保存中的结果不被缓存清理抢删             |
| 暂存与空间     | R2 冻结 TTL/预算后，低空间、输出不可写、缓存满、过期及断盘样本              | 记录暂存/发布占用、仅保存重试的引擎调用次数；实际故障使用隔离测试盘，R6 执行                        |

采样至少涵盖主进程、转换子进程与 WebView，记录进程集合与 100 ms 采样间隔；内存指标注明 RSS/PSS 或平台对应计数，不能混为同一种数据，注明采样可能漏过短时峰值。临时磁盘和最终输出分别统计，测量开销单列。总期限、取消和睡眠恢复场景继续按原生平台验证，不能以采样进程结束当成转换成功。
