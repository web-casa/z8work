# 网页引擎桌面版：后续开发与发行准备

日期：2026-09-20。分支 `feat/desktop-web-conversion`。
本轮按用户要求只开发、review 和测试，没有构建新的 app/DMG、提交公证或创建 Release。
此前签名候选不包含以下改动，不能作为这些改动的安装件验收证据。

## 开发改动

- Mac 增加 `applicationShouldTerminate:` 处理，把 Dock / AppKit 系统退出请求接入现有任务确认流程。保持 Tauri 的 delegate，只添加尚不存在的方法；SDK 行为变化时明确失败，避免覆盖框架方法。确认与取消都回复 AppKit 的待定退出请求。
- 保存过程在写入失败后禁止继续写入/发布，检查实际文件长度；磁盘满、权限不足给出操作建议。前端保留结果，可另选路径重试；超过 2 GiB 的输出在打开保存对话框前拒绝。
- 已知内存分配失败补充缩小文件、减少批量、关闭其他应用后重试的提示。不会把所有 WASM 越界错误误报为内存不足。
- 新增较大图片、批量 ZIP 和引擎加载中取消后重试的回归场景。
- 每次桌面前端构建根据 Vite 实际模块图和目标平台 Cargo 非开发依赖图收集许可（保守包含构建依赖）。许可随前端嵌入，通过致谢页的资源区域离线展开阅读，不离开当前应用会话。外链提供项目发行版本页，采取手动下载更新。
- 正式配置 `packaging/desktop-web/tauri.release.json` 使用名称 `Z8.Work`，保留 `work.z8.desktop.m0`，版本继续由基础 Tauri / Cargo 的 `0.2.0` 管理。没有为未发行的版本随意增加版本号。
- Mac 预览及签名工作流改为手动触发。签名使用明确的 `sign` 布尔输入，默认 false，并禁止同一次运行重跑时再次公证。旧提交标题 `[sign-macos]` 不再触发签名。

## 本轮 review 修复

- 发现手动化工作流后仍依赖 push 提交标题的签名条件会永远为 false，改为显式布尔输入。
- 压力回归中许可页一次性创建全部正文节点，测试页在 128 MiB JS 堆限制下崩溃。改为按组件展开时渲染，折叠时移除正文；同一限制下回归通过，并断言只存在当前展开的正文。
- 来源证明不能只检查 `verified` 标记，离线正文不能只检查组件数量：增加来源码归档、实际 WASM 和许可正文 SHA-256 校验及篡改回归。
- 明确 Mac AppKit 协议测试、模拟壳的浏览器测试和旧签名包 GUI 证据的边界，没有把它们当作新版本最终安装件已通过验收。

## 许可与对应源码：尚未关闭的发行项

`packaging/desktop-web/engines.json` 固定 5 个不同 WASM 的 SHA-256、已查证版本和源码线索（构建目录中的第 6 个文件是同字节重复资源）。当前 Mac ARM64 清单收集 310 个组件的许可，没有清单级缺失项；Linux 清单为 389 个。数量包含构建依赖，不等同于实际链接库数，也不代表嵌入库和对应源码已经全部审定。

1. **Pandoc**：二进制包含 `pandoc-3.5-inplace`，于 `a84837cff4177d0fe2bb13da7c2488ce33ca5726` 引入。上游版本版权文件已补齐，但仅凭标记不能确认 WASM 使用的确切 patched source、工具链、依赖版本。没有用 Pandoc 3.5 普通源码替代未知的 WASM 构建证明。
2. **FFmpeg WASM**：查到 core 0.12.10 的发布提交 `71aa99d37c02a7b4c435275ca9ef50e612f6efa1`，而同名 wrapper tag 不是该 core 的正确来源。该提交 Dockerfile 仍使用部分浮动库分支，完整源码归档需补充实际依赖提交。GPL 文本和 wrapper MIT 文本有独立来源及 SHA-256。
3. **Magick / MuPDF / vert-wasm**：记录 npm 包 gitHead / tag 来源、WASM 字节和包内许可。仍需针对最终发行归档并核对嵌入库、对应源码、补丁和构建输入。包内含 WASM 的 npm tarball 不自动等于对应源码。
4. 完整应用源码、锁文件和以上引擎材料应与最终发行版本一起提供；当前没有声称完成许可证兼容性审定或创建了完整源码发行包。

这些是具体的材料缺口，不是等待用户批准的流程。发布前应取得上游确切构建材料，或选择有可验证构建来源的引擎版本并重新验证转换兼容性。当前不擅自替换引擎版本。

## 后续命令（本轮未执行打包）

开发验证：

```sh
npm run desktop:check
npm test
cargo test --locked --manifest-path src-tauri/Cargo.toml
Z8_DESKTOP_TARGET=aarch64-apple-darwin npm run desktop:build
npm run desktop:test:stress
npm run desktop:release:check
```

`desktop:build` 仅构建静态前端和许可，不构建 app / DMG。收集器需要 Cargo、锁定依赖以及首次获取这些依赖的网络；应用运行及许可阅读不需要联网。默认许可目标为本机 Rust host，交叉构建须用 `Z8_DESKTOP_TARGET` 显式指定目标。

将来源码材料补齐后，每个 engine 的 `sourceEvidence` 应指向 JSON 证据，至少含 `wasmSha256`、`reviewedBy`、非空 `buildInputs`、本地相对路径 `archive` 及 `archiveSha256`；审阅者应实际核对源码完整性，哈希本身不证明源码合规。预检同时验证前端包含的全部 WASM、许可正文、锁文件及正式身份。它是材料一致性检查，不代替法律审阅、签名及最终包验收。

未来正式构建使用：

```sh
Z8_DESKTOP_TARGET=aarch64-apple-darwin npm run desktop:package:release -- --target aarch64-apple-darwin --bundles app,dmg
```

配置内的 `prepare` 在来源缺项时失败；满足材料检查后才重建前端和许可。此命令不自动签名、公证或上传。现有 `macos-candidate.json` 和签名 / GUI 脚本仍固定此前 **Dev 预览** 的名称与字节；正式包产生后必须更新候选信息并调整实际 app 路径，不能直接套用旧签名记录。

最后仍需新安装件上的 Dock / 会话注销 / 实际内存压力、保存权限及磁盘满验收。强制结束和断电无法依赖应用退出确认来保留内存中的任务，本轮没有增加重启恢复功能。
