# Linux 转换中清空列表与继续使用验收

日期：2026-09-14。承接[取消排队项验收](LINUX_CANCEL_QUEUED_ACCEPTANCE.md)，补齐活动转换期间清空整个列表及清空后继续使用的固定 deb 回归。本轮不修改生产队列或安装包。

## 实现与 review

新增 `desktop-packaged-clear-active.mjs`。通过既有真实 AVIF 编码进程的 SIGSTOP 注入构造一项 running、一项 queued，再通过工具栏可见 `Clear file list` 按钮聚焦并发送 Return。

要求清空操作结束后：

- 队列为空，processing、clearing、closing 均为 false；已观测编码进程消失，应用仍存活。
- 空列表产生新的 epoch，旧批次不再保留；原输出目录及本会话授权保持有效。
- 输出文件集合和内容与清空前完全相同，两份输入字节不变，不把移除任务误写成删除用户文件。

随后重新选择原微型 PNG，要求取得新任务 ID、attempt=0，通过可见格式控件及键盘转换为 WebP。结果必须以 attempt=1 在清空后的 epoch 中保存，WebKit 实际解码尺寸正确；输出目录仅增加这一项，旧文件及原件不变。无需重启应用；再次清空后新结果仍保留，外层卸载验收继续核对其摘要。

Review 修正：

1. 新场景最初漏入工具的独立 action 白名单。改为由同一份处理函数映射完成允许项检查和分发，避免两份名单漂移；不是生产界面的功能问题。
2. 清空不等于取消：除了终止编码，还要求旧任务全部移除、epoch 变更，以及新导入任务不会复用旧 ID。
3. 不只检查空白界面，还实际完成清空后的新转换，防止清理状态或授权状态卡住工作区。
4. 对原件和输出目录执行字节与文件集合检查，并要求新结果在清空及卸载后保留。
5. 门禁要求完整二十四组；旧二十二组、缺项、重复项、错误架构或应用哈希均拒绝。此前取消、退出、保存恢复等场景继续回归。

本轮未发现需要修改生产逻辑的缺陷，交付为验收覆盖和测试工具维护修正。
