# Linux 全部取消与显式重试验收

日期：2026-09-14。承接[单项取消与队列继续验收](LINUX_CANCEL_CURRENT_ACCEPTANCE.md)，补齐批量取消及取消后继续使用的最终 deb 回归。本轮不修改生产代码、引擎或安装包。

## 实现与 review

复用真实 AVIF 编码进程暂停夹具，构造一项 running、一项 queued，通过可见 `Cancel all` 按钮聚焦并发送 Return。检查两项均 cancelled、没有结果，队列不再 processing/clearing/closing，应用仍存在，已观测编码进程消失。输出目录必须与操作前完全一致，包括既有文件字节。

随后只通过第二项的 `Retry` 按钮显式重试，不使用批量转换按钮。要求第二项成功保存 WebP，attempt 从 1 增至 2；第一项仍 cancelled、attempt 为 1、没有结果。WebKit 必须实际解码输出且尺寸与源 PNG 一致。最终目录只新增重试项结果，原文件与既有结果保持不变；清空后结果保留，外层卸载验收继续核对其哈希。

Review 要点：

1. 单项取消、全部取消和原生退出共享夹具准备及进程身份检查，但使用明确的三种 action 分支；非法 action 在执行前拒绝，避免叠加布尔开关产生模糊组合。
2. 取消完成不能只靠按钮回执；要求终态快照、原生编码进程消失和文件目录一致性共同通过。
3. 重试只针对一个任务 ID，同时检查另一任务未增加 attempt、未生成结果，防止误触批量重新转换。
4. 前后文件集合精确比较，输出真实解码；新结果继续进入卸载后保留检查。
5. 新增两组检查，当前门禁要求完整二十组；旧十八组、缺项、重复项、错误架构或应用哈希均拒绝。

本轮未发现需要修改生产逻辑的缺陷，交付为批量取消与恢复能力的安装包验收增强。

## 验证记录

工具提交 `f0e27d9`；异常记录修正 `92fb426`。本机 Debian 13 ARM64 从固定 deb 解包运行，初版和 `8c9ee8d` 修正版的二十组 GUI 检查均通过（最终记录为修正版）；213 项脚本测试、修改文件 ESLint、Prettier 和差异检查通过。未在宿主机安装或卸载应用。

双架构 CI：[34803958102](https://github.com/web-casa/z8work/actions/runs/34803958102)。首轮 ARM64 通过，AMD64 在本轮新增两组检查通过后，后续原生退出场景未完成；原始报告只有 `Command exited 1`，未保留底层异常，根因未确认。

Review 补充：GUI 工具现会在清理驱动前保存 `failure.json`，记录原始消息、堆栈和有界 stderr，避免外层进程终止掩盖失败原因。本机使用不存在的测试 xdotool 路径做负向验证：运行非零退出、报告保持 failed，`failure.json` 正确保留 ENOENT 与堆栈（`diagnostic-probe/`）。这项预期失败不是产品验收失败或成功。第二轮 [34804208112](https://github.com/web-casa/z8work/actions/runs/34804208112) ARM64 通过、AMD64 在第二次导入时报告 `Picker did not open`。堆栈定位到 `choose(button-input)`；静态检查发现原驱动直接点击按钮，未等待格式修改/登记后的 UI busy 状态释放，禁用按钮的点击会被浏览器忽略。修正 `8c9ee8d` 在点击前有界等待按钮可用，并在选择器关闭后等待登记释放按钮；不强行启用控件、不直接调用导入 IPC。首轮底层异常仍无法追溯，不能断言与第二轮完全相同。第三轮 [34804433108](https://github.com/web-casa/z8work/actions/runs/34804433108) 两架构均通过，工具提交为 `8c9ee8d`。首轮证据保留在 `first-attempt/`，不计作双架构成功。

## 边界

使用 SIGSTOP 故障注入，覆盖一项活动 AVIF 编码加一项排队 WebP，以及取消后显式重试小图。不代表自然编码性能、大批次、等待保存时的全部取消、其他引擎、升级、Wayland、Snap strict 或 Windows/macOS GUI 已通过。既有十八组检查继续执行，R6 其他缺项保留。
