# Linux 已安装包保存恢复验收

日期：2026-09-14。承接[原生退出验收](LINUX_QUIT_ACCEPTANCE.md)，补齐 R6 所要求的 R2 保存恢复在最终安装包上的 GUI 回归。本轮复用固定哈希的 Linux deb；没有修改转换算法、生产界面、原生引擎或重打安装包。

## 实现与验收依据

新模块 `scripts/lib/desktop-packaged-save-checks.mjs` 接入现有 `--packaged-product`，在原先九组检查之外增加三组检查。导入、格式选择、转换、目录切换和清空通过现有可见控件执行；“仅重试保存”通过聚焦按钮后发送真实 Return 键触发。IPC 只读取状态，不绕过界面提交转换或保存。

1. 使用仓库微型 PNG 的独立副本，在专用目录生成 1,000 个候选同名文件。实际转换完成后因输出命名冲突进入 `awaiting_save`。确认状态、错误类型、attempt 为 1，并读取应用私有缓存中的实际 WebP。
2. 打开原生保存目录选择器后按 Escape。确认原输出目录及授权保留、attempt 未增加、任务仍等待保存，缓存逐字节不变。
3. 将测试副本临时改名，确认原路径不存在。通过原生目录选择器换到可写的结果目录，再以键盘触发“仅重试保存”。要求任务保存成功、原路径仍不存在、输出字节与之前捕获的缓存完全相同，且暂存载荷释放。
4. 在 `finally` 中恢复测试副本并核对原始字节；核对所有 1,000 个冲突文件内容未变。清空任务后，再确认保存结果和恢复的测试原件均保留。此前正常转换得到的结果也由原生退出回归继续校验。

这里的“源文件不可读”仅指测试副本的原路径在保存期间不存在。脚本不会移动用户文件，不会修改输入仓库夹具，也没有把故意移走的测试副本误写成应用造成的丢失。

## Review 与修正

- 复用了已有私有缓存检查函数和原生 portal 驱动，不新增生产 IPC。取消选择同时检查实际 `output` 字段和 `output_authorized`，避免比较不存在的属性产生假阳性。
- 检查真实缓存与落盘字节，而不是只检查扩展名、文件存在或 UI 文案。保存结果必须落在新选择的目录。
- 原生队列每次提交都会递增 attempt，保存提交也包含在内。因此本次正确预期是 1 → 2，不能用 attempt 不变作为“没有重新编码”的证明。本验收以输入原路径不存在时仍成功保存完全相同的缓存为依据；没有对最终二进制注入引擎调用计数器。
- 保存成功后检查缓存载荷释放；临时输入移动放在 `try/finally` 范围内恢复。
- 当前门禁要求全部十二组检查，拒绝旧九组报告、缺项、重复项、失败状态、错误架构或错误应用哈希。历史九组报告保留当时的通过结论，不满足新增门禁。

本轮未发现需要修改生产保存逻辑的缺陷，交付内容是最终包验收覆盖及门禁增强。
