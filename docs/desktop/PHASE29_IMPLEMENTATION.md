# Phase 29 / R6：真实文件系统故障与平台兼容性

日期：2026-09-10。代码提交：`0b22fb5`。本轮完成可在当前 Linux ARM64 环境独立执行的故障验证、缺陷修复与 review；**R6 整体验收未完成，R7 未开始**。R5 的 macOS 实际候选、PDF ICC 与完整对应源码/许可缺项继续保留，见 [Phase 28](PHASE28_IMPLEMENTATION.md)。

## 实现与修复

新增 `desktop:test:faults` 和仅在 `engine-validation` 下构建的 Linux `fault-check`。验证器复用实际 `convert_source`、文件发布、会话暂存与 `PendingOutput::save`，不注册桌面 IPC，也不编译进正式应用的功能入口。

故障在普通 UID、断网、只读根目录的 scratch 容器执行。三个独立 tmpfs 各 32 MiB，inode 测试卷限 64 项；容器限制 1 GiB 内存、2 CPU 和 128 个进程。验证器检查实际文件系统类型、容量、只读状态、目录非符号链接且为空，才允许注入故障。磁盘填充有 64 MiB 上限，不对服务器磁盘进行填满测试。执行器校验平台、引擎清单和验证器摘要，限制运行时间/日志大小，并清理本次 UUID 对应容器和镜像；清理失败也不能报告通过。

| 实际故障                 | 验证结果                                                                          |
| ------------------------ | --------------------------------------------------------------------------------- |
| 真实只读挂载             | 输出预检拒绝，分类为输出权限错误                                                  |
| inode 耗尽               | 创建 63 个文件后实际触发 ENOSPC；复现并修复错误分类                               |
| 编码完成后磁盘耗尽       | 填入 33,488,896 字节至 ENOSPC，发布失败仍保留已验证结果；故障未解除时重试继续失败 |
| 编码完成后撤销目录写权限 | UID 1000 下将目录改为 0500，发布和原目录重试均失败，已编码结果保留                |
| 会话暂存清理             | 释放待保存对象和工作区后，没有残留的会话目录                                      |

后两种故障均验证：输入字节和已有输出不变、没有部分发布文件；移走原输入路径后，直接重试保存到健康目录成功。目标已有 `source-z8-1.png` 时生成 `source-z8-2.png`，保留已有文件，并对保存结果重新解码、比较像素。仅保存调用本身不接收引擎或输入文件；后续解码属于测试验证。

实际暴露的生产缺陷是：`storage` 返回 `insufficient free file entries`，而 `Failure::classify` 只识别旧措辞 `free file slots`，导致 inode 耗尽被归入普通发布失败。已加入现有措辞识别及输出目录/暂存目录回归测试。保留修复前真实失败和修复后真实通过记录，没有用合成报告替代故障执行。

## macOS 兼容性门禁

此前只核对 ARM64 架构与依赖闭包，不能区分同架构的 iOS 二进制，也不能识别引擎要求的系统版本高于 `.app` 声明的情况。本轮解析 `LC_BUILD_VERSION` 和旧版 minimum-version 命令，要求实际 macOS 平台及有效最低版本，拒绝重复、畸形、缺失的部署信息。主程序及每个 Mach-O 资源都必须满足配置中的最低系统版本。

校验接入资源组装、`.app` 候选及 macOS CI 应用检查，报告保留实际部署字段。合成 Mach-O 回归覆盖 iOS、其他旧版平台命令、过高最低版本、非法版本、重复命令、错误工具数量，以及合法的新旧 macOS 命令。定义已核对 [Apple 的 Mach-O loader.h](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/EXTERNAL_HEADERS/mach-o/loader.h)。静态检查通过仍不能替代最低支持系统上的真实运行、签名和干净账户验收。
