# Linux 未保存结果与原生退出验收

日期：2026-09-14。承接[已安装包原生界面验收](LINUX_GUI_ACCEPTANCE.md)，补齐此前由 WebDriver 结束应用会话所不能证明的原生关闭流程。本轮仍使用哈希固定的既有 deb；没有修改或重编应用、引擎及安装包。

后续[保存恢复验收](LINUX_SAVE_RECOVERY_ACCEPTANCE.md)把安装包 GUI 门禁扩展到十二组；本页保留本轮九组验收的历史范围。

## 范围与实现

复用 `desktop-quit-window.py` 向测试窗口发送 `WM_DELETE_WINDOW`，进入应用自己的关闭处理。确认按钮通过 PID 限定的 AT-SPI 查找并点击；先确认应用 PID 消失，才删除已退出的 WebDriver 会话。因此本轮原生退出不是由删除 WebDriver 会话或强杀进程造成的。

在独立测试目录创建 1,000 个候选输出同名文件，将微型 PNG 转为 WebP。转换完成但保存因名称冲突失败，任务进入 `awaiting_save`，实际 WebP 结果留在应用私有缓存中。随后验证：

- 连续关闭主窗口只出现一个确认框；Escape 返回应用，任务仍等待保存，attempt 保持 1，缓存字节不变。
- 再次关闭并按默认回车，应用继续运行，缓存字节不变。
- 点击明确的 `Stop and quit` 后应用退出；在重新启动前确认先前的 WebP 缓存文件已删除。
- 重启后任务变为 `interrupted`，attempt 仍为 1，没有自动恢复转换；输入及输出目录都需要重新授权。原件、上一轮已保存文件以及 1,000 个冲突文件的内容全部保留。
- 等待引擎初始化完成后，在没有活动任务或未保存缓存时关闭原生窗口，应用直接退出且不显示确认框。

本轮针对的是**转换已完成、结果等待保存**的状态；不将其称为正在编码时的进程树取消验收。

## Review 修正

1. 暂存检查从文件存在加强到逐字节核对，避免将损坏或被改写的缓存误认为保留成功。
2. 仅要求已观测到的 WebP 暂存载荷被删除，不要求整个 session 目录消失。`lease.json` 等延迟回收标记不等于仍持有转换结果。
3. 通过有效的窗口 PID 确认实际退出，并在空闲退出前等待引擎就绪，避免把启动期间的确认语义混入空闲场景。
4. 已安装 GUI 门禁从五组扩展到九组检查；旧五组报告、缺项及重复项均不能通过当前门禁。原有五组导入、转换、重启及清空检查继续执行。
5. CI 显式补齐 Python GI、AT-SPI introspection 与 `at-spi2-core` 总线服务依赖，复用原有双架构原生 runner、固定 deb 来源、安装/卸载及报告归档流程。

没有发现需要修改生产退出逻辑的缺陷；本轮交付为验收工具与门禁增强。旧文档和旧报告保留当时的覆盖范围。
