# Linux 排队任务退出验收

日期：2026-09-14。承接[活动编码进程退出验收](LINUX_ACTIVE_QUIT_ACCEPTANCE.md)，补齐“一个活动任务加一个尚未开始的排队任务”的最终安装包回归。不修改生产队列、转换算法或包文件。

后续[单项取消与队列继续验收](LINUX_CANCEL_CURRENT_ACCEPTANCE.md)补齐取消活动任务后下一项实际保存，门禁扩展为十八组；本页保留原十六组覆盖范围。

## 实现

扩展现有 `desktop-packaged-active-quit.mjs`，继续通过真实文件选择器导入合成大图并选择 AVIF，随后导入微型 PNG 副本并选择 WebP。通过可见转换按钮一次提交两项任务。复用此前对真实 AVIF 编码进程的 SIGSTOP 注入，使第一项稳定处于 running，第二项处于 queued。

- 关闭前必须恰好有两项任务；按任务 ID 核对第二项为 queued、没有 result。
- 连续关闭只出现一个确认框；Escape 后第一项仍 running、第二项仍 queued，暂未产生第二项结果。
- 明确选择停止并退出后，应用与已观测的编码进程退出，批次输出目录为空。
- 重启时两项均为 cancelled，输入和输出授权均未恢复。等待引擎初始化完成后再次读取快照，仍无自动运行，输出目录为空，两份原件字节不变。
- 新增 `queued-details.json` 保存关闭前、Escape 后及重启就绪后的原始快照，并保存排队项截图。现有保存恢复和未保存结果退出检查继续运行。

## Review

1. **排队不是未提交。** 原生队列提交批次时即递增 attempt；尚未编码的第二项正确值也是 1。验收使用明确的 queued 状态、任务 ID、无 result 和空输出目录，不把 attempt 当作引擎调用次数。
2. **不只检查重启第一帧。** 等引擎全部就绪后再次核对 cancelled、processing 与授权，避免只在启动早期观察到未运行就判定恢复正确。
3. **保留原有故障注入边界。** 第一项使用实际 AVIF 编码进程，仍核对父进程、启动时间、包内加载器、引擎参数和隔离工作目录；本轮不扩大为所有引擎或任意进程树测试。
4. **门禁同步更新。** 要求全部十六组 GUI 检查，旧十五组、缺项、重复项和错误身份报告不能通过。历史报告仍保留当时的验收范围。

本轮交付为批量队列验收覆盖，未发现需要修改生产队列逻辑的缺陷。

## 边界

这是单个活动任务加一个排队任务的故障注入验收，不覆盖更大批次、正常编码速度下的所有退出竞态、单项取消后自动处理下一项、强杀、断电、升级、Wayland、Snap strict 或 Windows/macOS 原生界面。其他引擎及 R6 剩余验收继续单列。
