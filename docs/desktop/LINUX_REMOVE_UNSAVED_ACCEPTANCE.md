# Linux 单项移除与其他暂存结果保存验收

日期：2026-09-14。承接[等待保存时清空列表验收](LINUX_CLEAR_UNSAVED_ACCEPTANCE.md)，补齐多项等待保存时只移除一项的固定 deb GUI 回归。生产代码与安装包不变。

## 实现与 review

新增 `desktop-packaged-remove-unsaved.mjs`，复用保存恢复场景的隔离目录与原生文件选择器。使用不同内容和尺寸的 32×32、48×24 PNG，分别准备 1000 个文件名碰撞文件，实际编码为 WebP 后要求两项均进入 `awaiting_save`，attempt=1，且没有已发布结果。

通过 WebKit 解码两份缓存载荷并检查字节不同，确定每份载荷的归属。聚焦第一项可见 `Remove task` 按钮并发送 Return，要求：

- 仅第一项从队列移除，第二项完整任务快照不变；epoch、输出目录及授权保留。
- 第一项的具体缓存路径消失，第二项的缓存路径和字节不变；同一应用进程仍存活。
- 原文件、2000 个碰撞文件以及已有保存结果不变，结果目录无新增文件。

随后临时移走第二项的合成源文件，使用真实目录选择器改选可保存目录，用键盘操作 `Retry saving only`。要求第二项以同一 ID、同一 epoch、attempt=2 保存，磁盘结果与保留缓存逐字节相同，实际解码为 48×24；源文件在保存期间确实不存在，finally 恢复原件。再清空后结果仍保留，外层卸载检查继续核对摘要。

Review 重点：

1. 两项不能使用相同内容的样本，否则误保留第一项缓存也可能得到相同输出。按真实解码尺寸和不同字节区分载荷，不猜测缓存目录名称与任务 ID 的关系。
2. 单项移除不应重置剩余批次；要求第二项完整快照不变及 epoch 不变，区别于清空列表。
3. 具体缓存路径的 ENOENT 才表示载荷已释放，其他读取错误不得吞掉；对用户文件执行集合和内容校验。
4. 保存阶段在隔离目录中移走源文件，确保没有通过重新读取源文件完成转换。恢复使用 finally，所有外部文件操作仅针对合成测试资产。
5. 门禁扩展为二十八项，旧二十六项或缺项、重复、错误状态/架构/应用哈希均拒绝；此前场景继续完整回归。

## 边界

本轮新增覆盖两项 WebP 文件名碰撞造成的等待保存，移除第一项后保存第二项。不替代活动任务单项移除、多页 PDF 暂存、大批次、磁盘故障、升级、Snap strict 或 Windows/macOS GUI 验收。原有活动转换回归仍包含 SIGSTOP 注入，R6 整体继续保留缺项。
