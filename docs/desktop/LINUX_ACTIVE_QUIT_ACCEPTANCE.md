# Linux 活动编码进程退出故障注入验收

日期：2026-09-14。承接[保存恢复验收](LINUX_SAVE_RECOVERY_ACCEPTANCE.md)，把既有开发环境的暂停编码进程方法接入最终 deb 的原生 GUI 回归。本轮不修改应用、引擎、安装包或发行版本。

## 范围与方法

以固定哈希的完整 deb 运行，复用现有 portal、WebKit 驱动和 `desktop-quit-window.py`。输入由随包 ImageMagick 在隔离目录生成，为 2048 × 2048 的合成 PNG；通过可见控件导入并选择 AVIF，再点击转换按钮。

测试先观察属于应用 PID 的真实 ImageMagick 进程，核对启动时间、实际加载器路径、命令参数中明确的 AVIF 输出及隔离工作目录。随后对该进程发送 `SIGSTOP`，并要求 `/proc` 状态变为 `T`。这是**人为暂停真实编码进程的故障注入**，不代表在编码器正常获得 CPU 的条件下测量转换或退出性能。

- 任务必须处于 `running`、processing 为 true、attempt 为 1。
- 连续请求关闭主窗口只出现一个原生确认框；Escape 返回应用后，任务仍运行，编码进程仍保持注入的暂停状态。
- 再次关闭并明确点击 `Stop and quit`。要求应用和此前观测到的编码进程均退出，确认后才删除 WebDriver 会话。成功路径不由测试工具杀死编码进程，也不主动恢复该进程。
- 取消后目标目录没有输出或临时文件，原 PNG 字节不变。重启后任务为 `cancelled`、attempt 为 1，输入及输出授权均未恢复；等引擎就绪后仍无自动发布，清空历史后继续原有未保存结果退出检查。

取消后的实测耗时只作诊断记录，不作为性能基准；应用退出和编码进程消失均有有界等待，超时为失败。故障清理中的 `SIGCONT` 只用于恢复尚存的测试进程，不能计作应用成功取消。

## Review 与修正

1. **最终包启动方式与旧开发测试不同。** 早期本地测试直接执行 `magick`，缺少私有动态库而失败。改为读取 `engines.json`，使用包内 loader、library_dir、ImageMagick 配置、模块及 HEIF 插件目录生成夹具；应用自己的转换仍走生产启动逻辑。
2. **避免把格式探测当作编码。** 仅识别 ImageMagick 子进程不足以证明进入转换。最终实现额外检查 `-auto-orient`、AVIF 编码参数、`AVIF:…output.avif` 输出以及隔离缓存工作目录，并归档实际参数。
3. **信号目标收紧。** 发送信号前重新核对 PID 启动时间、父进程、可执行文件及引擎参数；PID 已消失时不发送，身份不符时拒绝。新增真实测试子进程验证过期身份、错误父进程、错误可执行文件和错误引擎参数均不能触发暂停；暂停与恢复也做实际检查。这是测试进程管理，不是生产进程管理重构。
4. **门禁与证据范围一致。** 原十二组 GUI 检查继续执行，加三组后要求完整十五组；旧十二组、缺项、重复项、错误架构或应用哈希均不能通过。只声明已观测编码进程退出，不把单进程检查扩大成任意进程树穷举。

早期生成夹具失败及收紧进程筛选之前的本地记录与最终记录分开保存。没有发现需要修复生产退出逻辑的缺陷。

## 边界

本轮未验证无故障注入时所有编码器的退出时序，也未覆盖队列中多个待执行任务、任意后代进程树、强杀应用、断电、睡眠唤醒、旧版升级、Wayland、Snap strict、Windows/macOS GUI 或商店审核。FFmpeg、Pandoc、MuPDF 的活动退出不由本轮 ImageMagick 结果替代。GUI 未断网，离线能力仍引用独立验收。原 R6 的其他缺项继续保留。
