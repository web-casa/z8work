# Linux 取消当前任务与队列继续验收

日期：2026-09-14。承接[排队任务退出验收](LINUX_QUEUED_QUIT_ACCEPTANCE.md)，补齐单项取消对后续任务的影响。本轮复用固定 deb，不修改生产取消逻辑、转换算法或安装包。

后续[全部取消与显式重试验收](LINUX_CANCEL_ALL_ACCEPTANCE.md)扩展到二十组门禁；本页保留原十八组覆盖范围。

## 实现与 review

在现有真实 AVIF 编码进程暂停夹具中增加独立场景：第一项为合成 PNG → AVIF，第二项为微型 PNG → WebP。确认第一项 running、第二项 queued 后，通过第一项可见的 `Cancel task` 按钮聚焦并发送 Return，触发正常的单项取消。测试不直接发送取消 IPC。

新增模块 `desktop-packaged-cancel-current.mjs` 要求：

- 应用保持打开，第一项 cancelled 且没有结果，观测到的 AVIF 编码进程消失。
- 第二项无需再次点击转换即变为 saved，attempt 仍为本次提交的 1；队列停止 processing，未进入 closing。
- 实际输出是 WebP，字节长度与原生结果记录一致，WebKit 能解码且宽高与第二项源 PNG 一致。
- 输出目录只新增第二项的结果；原有已保存文件、两份输入字节均不变。清空任务后再次核对新结果与输入保留。
- 新结果放入既有结果目录，继续被外层安装验收的卸载后哈希检查覆盖。

Review 重点与修正：

1. 沿用按 PID、启动时间、父进程、包内加载器与编码参数限定的故障注入，只暂停被测应用的 AVIF 编码进程。新模块复用现有准备与失败清理，不复制一套进程控制逻辑。
2. 取消后不仅检查 UI 状态，还要求编码进程消失、应用存活、下一项实际落盘并成功解码。没有将“收到取消请求”当作完成取消。
3. 输出目录在操作前记录文件名与原始字节，操作后要求精确增加一个结果，防止只检查目标文件存在而漏掉取消项误发布、额外临时文件或原结果被覆盖。
4. 使用任务 ID 区分取消项与继续项。新增两组检查后，当前门禁要求完整十八组；旧十六组、缺项、重复项、错误架构/应用哈希不能通过。

本轮未发现需要修复生产代码的缺陷，交付为实际安装包验收增强。

## 边界

本轮仍是 SIGSTOP 故障注入，验证一个 AVIF 任务取消后一个 WebP 任务继续；不代表自然编码时序性能、其他引擎、大批次、取消排队项、全部取消、升级、Wayland、Snap strict 或其他系统 GUI 已验收。既有活动退出、排队退出、保存恢复及未保存结果退出继续回归，R6 其他缺项仍单列。
