# Phase 2 / M2：格式、参数与批量交互

日期：2026-09-08。延续 [Phase 1](PHASE1_IMPLEMENTATION.md) 和 [补充 review](PHASE1_FOLLOWUP_REVIEW.md)，本轮开发 M2 的原生转换与交互。验证环境仍为 Debian 13 / Linux ARM64，使用显式指定的开发引擎；跨平台安装、自包含引擎和商店门槛未因此通过。

## 1. 已实现

| ------------------ | ------------------------------------------------------------------------------------------------------------------------------ |

| PDF 部分完成       | 每页保存后更新 Rust 历史；失败或取消保留成功页。显式重试时核对输入哈希、格式、参数、引擎身份和输出字节，符合条件才跳过已完成页 |
| 音频与视频提取音频 | WAV、MP3、FLAC、Opus、M4A 五种输出；只提取首条音轨，校验完整解码、时长与声道，不提供视频转码                                   |

| 原生拖入           | 接收 Tauri 的 OS 文件拖放事件，复用原生登记、类型/大小检查与队列空闲限制；拒绝转换中或选择器打开时导入                         |

## 2. 实际格式范围和参数

| 输入                                 | 输出                      | 明确限制                                                                |
| ------------------------------------ | ------------------------- | ----------------------------------------------------------------------- |
| PNG、JPEG/JPG、WebP、AVIF、HEIC/HEIF | PNG、JPEG、WebP、AVIF     | 首帧；JPEG 使用白色背景；其他原生图片格式尚未开放                       |
| PDF                                  | 同上四种                  | 全部页面；输出图片分别保存，不打 ZIP；加密/无效 PDF 报错，不提供密码 UI |
| MP3、WAV、FLAC、OGG、Opus、M4A       | WAV、MP3、FLAC、Opus、M4A | 首条音轨；WAV 为 PCM 16-bit，MP3/AAC/Opus 为有损；来源元数据和章节移除  |
| MP4、MOV、MKV、WebM                  | 同上五种音频格式          | 需要存在音轨；不导出视频，不启用任意滤镜                                |
| Markdown、DOCX                       | TXT                       | 保留纯文本；图片、布局和排版不保留，不宣传文档保真互转                  |

界面格式来自 Rust 路线表，并按所需引擎的完整性检查过滤。没有用 `--version` 或列表探测充当编码验证。本轮用当前开发清单实际转换并解码 76 条路线：20 条图片、50 条音频/视频音轨、4 条 PDF、2 条文档；JPEG/JPG、HEIC/HEIF 等别名共用明确的 decoder。这里的实测矩阵仅适用于本次开发引擎，其他安装包必须重新验证 codec/动态库和全部承诺路线。运行时依赖若被替换或缺少 codec，转换会明确失败，不尝试云端或切换格式。

质量预设属于项目选择，不是各编码器间等效画质的承诺：

| 预设     | AVIF quality | JPEG/WebP quality |
| -------- | ------------ | ----------------- |
| 更小体积 | 45           | 65                |
| 均衡     | 60           | 80                |
| 更高画质 | 80           | 92                |

AVIF 固定 `heic:speed=6`、`heic:chroma=420`，WebP 使用 `method=4` 且不进入 lossless 模式。PNG 的 quality 值控制压缩，不作为画质比例。本轮未提供“100 就是无损”的开关。相关接口核查见 [ImageMagick defines](https://imagemagick.org/defines/)、[WebP 参数](https://imagemagick.org/webp/)；质量数值和性能策略仍需在最终各平台编码器上重新校准。

固定种子、256×256 合成样本的首轮校准结果如下，仅作为该样本的回归记录；最终执行结果以证据 JSON 为准，不把它推广为任何图片都更小或等效视觉质量：

| 格式 | 更小体积 | 均衡     | 更高画质 |
| ---- | -------- | -------- | -------- |
| AVIF | 1,943 B  | 4,623 B  | 15,405 B |
| WebP | 4,746 B  | 8,204 B  | 21,210 B |
| JPEG | 7,160 B  | 10,691 B | 32,280 B |

## 3. 保存、预算与恢复

PDF 使用 [mutool show](https://mupdf.readthedocs.io/en/1.28.3/tools/mutool-show.html) 查询页数，并调用 [mutool draw](https://mupdf.readthedocs.io/en/latest/tools/mutool-draw.html) 逐页渲染。具体参数还核查了本机 MuPDF 1.25.1 的 CLI 帮助，不直接假定最新文档功能都存在于开发版本。

- 普通输入最多 512 MiB，PDF 最多 100 MiB、200 页；PDF DPI 可选 72/96/144，渲染宽高各最多 4000 像素，较大页面会按比例缩小。
- 单任务保存的结果合计最多 256 MiB。PDF 逐页释放渲染和编码临时文件，不把所有像素或结果正文放入 WebView。
- 普通任务总期限 120 秒，PDF 总期限 900 秒；每个子进程另受至多 120 秒限制，总期限不会随进度重置。ImageMagick 和 MuPDF 继续设置各自资源预算。
- FFmpeg 设置输出大小限制，仍须通过体积、时长、声道与完整解码检查才能保存。时长差超过 0.2 秒会拒绝发布结果；这会保守拒绝时长元信息不可靠的输入，保留原文件。
- 输出按 `<原名>-page-001-z8-1.ext` 等命名，发生冲突递增后缀；文件名按 UTF-8 字节预留长度，避免合法长 emoji 原名加页码后无法保存。
- 已验证的页面逐文件原子发布，再更新历史。输出与历史不是跨文件事务；崩溃窗口内可能已有结果但记录尚未更新，仍须检查输出目录。
- 重试只复用同一输入字节、选项、格式、引擎身份及当前授权输出目录下哈希相同的页面。被删除、修改、越界或符号链接结果不作为可复用页。改变输入或参数会重新转换，不覆盖旧文件。

记录位置沿用 `app_data_dir()/queue-v1.json`，文件名不作为 schema。schema 1 的原记录备份为 `queue-v1.v1-backup.json`，冲突时拒绝覆盖，schema 2 保存后旧程序不会把新记录当作兼容数据。该迁移备份用于手动回滚，会保留旧任务名称与结果路径；清空新队列不删除迁移备份或磁盘结果。

## 4. Review 与修正

| 问题                                             | 处理与验证                                                                                                       |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| PDF 原型只转换第一页                             | 改为逐页处理；验证三页不同尺寸和页序，四种输出都独立解码                                                         |
| 页面已保存后取消，后续重试可能全部重复输出       | 每页报告并保存部分结果；真实引擎在第一页后取消，重试保留已保存页；GUI 五页 PDF 在刷新后重试，最终正好五个结果    |
| 变更参数后旧请求仍可能使用旧界面状态提交         | 提交绑定已登记 options，参数变更后的旧请求被拒；批量配置出错不部分生效                                           |
| 非法 DPI、重复页等不应进入 UI/历史               | Rust 校验参数和记录，前端验证 schema、质量、DPI、页数和重复页；共享快照 fixture 同时测试                         |
| 文件名伪装成媒体格式，FFmpeg 自动识别成播放列表  | 指定允许的输入 demuxer，MOV 禁用外部引用和绝对路径别名；伪装 `.mp4` 播放列表被拒，不执行其中的路径               |
| 仅能解码输出不足以保证没有截断音轨               | 增加时长与声道校验；76 条真实路线覆盖了相关成功流程，失败不发布输出                                              |
| “打开所在位置”可能变成通用打开任意路径的入口     | 仅暴露任务/页标识；重新检查目录授权、真实路径和哈希，拒绝虚构/修改结果；未给前端 opener 通用权限                 |
| 长 Unicode 名称加 PDF 页码后超长                 | 限定原名 UTF-8 字节数；实际 emoji PDF 输出验证通过                                                               |
| 单个引擎缺失使所有类型都不能转换                 | 按所需引擎过滤路线；删除 Pandoc 开发清单项后仍实际转换 AVIF                                                      |
| 生成 DOCX 测试样本时遇到开发 Pandoc 数据布局问题 | 改用仓库内自行生成的最小 OOXML fixture，独立验证 DOCX→TXT；没有为构造测试输入关闭产品 sandbox，DOCX 输出仍未开放 |

FFmpeg 的容器/编码选项依据本机帮助与 [官方 codec 文档](https://ffmpeg.org/ffmpeg-codecs.html)。Pandoc 继续使用 [sandbox](https://pandoc.org/MANUAL.html#option--sandbox)，没有添加用户过滤器或远程资源下载。

## 6. 完成边界

M2 本机功能开发与 review 不等于整个 V1 或跨平台 M2 发行验收完成。Windows/macOS、MSIX、strict Snap、自包含动态库、最终包 codec 矩阵、ICC/方向/特殊色彩完整回归，以及引擎许可证材料仍需按 M0/M3 推进。

原生拖放已接入真实 Tauri 事件与登记流程，并核对了已安装 runtime 的事件转发源码；本轮 GUI 自动化使用 GTK 文件选择器，没有实际执行文件管理器拖入、成功唤起系统文件管理器和拒绝权限后的平台恢复操作。这些不能被计为已通过实机验收。任务中退出确认、预览/缩略图、文件关联、完整文档格式与带图片排版、完整视频处理也未在本轮扩大范围。

保持此前关于非 OS 沙箱、恶意并发改写、阻塞文件系统、强杀后的进程回收、临时文件崩溃清理和掉电持久性的限制。下一阶段优先补齐自包含引擎与实际安装/授权门槛，再扩大格式或发布渠道。
