# Pixel Desktop 第二轮 review

日期：2026-09-06。审查当前像素界面与转换队列的衔接，重点检查取消、排队、失败恢复、参数编辑和归档输出。本轮发现以下问题，均已修复并复验。

| 优先级 | 问题与复现                                                                                                                          | 修复                                                                                                                                                |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1     | 单并发下取消首个图片或文档任务，下一项一直等待：终止 Worker 没有结束等待消息的 Promise。ZIP 子任务和 SVG 中间转换也未正确关联取消。 | 增加可取消的 Worker 消息等待，统一清理监听器与超时；取消时结束等待并释放队列。ZIP 跟踪正在转换的子文件，未启动条目跳过；SVG 中间文件继承原文件 ID。 |
| P1     | 批量任务排队后移除文件，队列中的闭包仍会启动其转换。                                                                                | 显式记录排队状态，任务启动前确认文件仍在列表且没有取消；允许直接取消排队项，并阻止重复启动同一批次。                                                |
| P2     | 损坏图片显示失败后，进入设置再返回，状态变成“待转换”。                                                                              | 将失败状态从组件局部变量移到文件模型；路由切换保留状态，修改目标格式时重置。                                                                        |
| P2     | 全部转换完成后只剩下载按钮；修改质量后没有重新转换入口。                                                                            | 增加“重新转换”，复用原批量转换流程。已有下载入口保留。                                                                                              |
| P2     | 质量输入显示 101，但实际保存 100；输入 0 也错误地保存为 100。                                                                       | 输入与保存值统一取 1–100 的整数；空值恢复先前设置。验证实际发送给转换 Worker 的质量参数。                                                           |
| P2     | ZIP 内 JPEG 转成 PNG 后，内容已是 PNG，但文件名仍以 `.jpg` 结尾。                                                                   | 按转换结果的实际扩展名写入归档，也兼容引擎返回 ZIP 的情况。下载后解压核对条目名与 PNG 文件头。                                                      |

实现沿用 `VertFile`、files store、现有转换器、设置与翻译体系。新增 `src/lib/util/worker-message.ts` 供 ImageMagick 和 Pandoc 共用；转换版本检查防止过期任务覆盖新结果。

## 验证结果

- `bun run test`：8/8，通过。覆盖主动取消、提前取消、消息阶段匹配、加载失败、转换错误信息、Worker 异常、超时清理和下一次等待不受旧任务影响。
- `bun run check`：0 errors / 0 warnings。
- `bun run build`：生产构建成功。
- 本轮修改文件及新增测试的 Prettier、ESLint：通过；`git diff --check`：通过。
- 生产预览上的 Chromium 回归：9/9，通过；各场景未处理页面异常为 0。完整结果：[regression-results.json](regression-results.json)。

浏览器覆盖：失败状态跨页面保留、质量边界与重新转换、取消活动图片、移除排队文件、取消排队文件、取消文档、取消 ZIP 子任务、ZIP 输出扩展名、取消 SVG 中间转换。重新转换实际下载 WebP 并校验文件头；文档实际完成 Markdown → DOCX；ZIP 实际解压验证两个 PNG 条目。

为稳定复现排队边界，取消场景将浏览器并发数设为 1，并暂时扣住首个 Worker 的转换消息。取消后检查后续任务实际完成、已取消或移除的任务没有启动；正常任务仍使用原转换 Worker。测试没有用模拟成功结果替代转换输出。
