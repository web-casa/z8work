# 常用格式选择与代码复查

日期：2026-09-07。对应[体验优化方案](PLAN.md)的 UX-04，延续已有工作区、品牌和转换能力。

## 实现

继续使用共享的 [FormatDropdown.svelte](../../src/lib/components/functional/FormatDropdown.svelte)，同时覆盖单文件、批量设置和设置页的默认格式。

- 图片优先展示 JPEG、PNG、WebP、AVIF、GIF、TIFF；音频和文档分别显示自己的常用格式。每个入口先按现有转换器计算合法候选，再筛选常用项；这份展示配置不声明新的转换能力。
- 增加简短用途说明和“显示数量 / 总数量”。例如 PNG 对应截图与透明背景，AVIF 提醒编码较慢。文案不保证文件一定变小，也不承诺恢复已经丢失的质量。
- “展开全部格式”显示其余候选；折叠时移除其他选项的 DOM。JPG/JPEG、TIF/TIFF 等扩展名保留为独立选项，当前已选别名优先显示在常用组，不修改目标扩展名。
- 搜索始终覆盖完整合法集合，忽略大小写、首尾空白和扩展名前导点，精确命中优先；清空搜索后回到分类。没有常用项时直接展示完整候选。
- 重开菜单时，如当前目标为 QOI 等非常用格式，自动展开并滚动到已选项。展开、折叠、关闭均不更改目标或结果。
- 面板内部只滚动结果列表，标题、关闭、搜索与计数保持可见。Tab / Shift+Tab 首尾循环；手机初始聚焦关闭按钮，桌面聚焦搜索，关闭后恢复原触发器。
- 新增 22 条文案，完整提供 en、es、zh-Hans、zh-Hant；其余语言仍采用英文回退。

## 复查与修正

本记录为实现者自审及自动化验证，不作为独立审查人批准。

| 检查项             | 发现与处理                                                                                                                                      |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 搜索范围与能力限制 | 搜索使用原始合法候选；常用项仅参与显示排序。PDF 仍完整提供原有 23 种输出，不出现 HEIC、PDF 或 MP3 输出。图片/PDF 混合队列维持原有分别设置规则。 |
| 空白查询           | 原先用原始 `query` 控制分类、用标准化查询控制结果，输入空格或单点时二者不一致。统一使用 `normalizedQuery`。                                     |
| 搜索滚动位置       | 实测在长列表底部搜索后保留旧滚动位置，首个匹配项位于可视区之外。查询或分类改变时重置结果区滚动，确保从首个结果开始浏览。                        |
| 键盘边界           | 实测从列表末尾按 Tab 会离开面板。新增首尾循环，保留原生对话框的背景隔离、Escape 和关闭焦点恢复。                                                |
| 手机长列表         | 用途说明增加高度，整张对话框滚动会带走搜索与关闭。改为结果区滚动，展开后仍能直接搜索或退出。                                                    |
| 格式别名与选中项   | 别名不合并，不修改下载扩展名；非常用目标在重开时自动展开。选择相同目标继续沿用现有无操作行为。                                                  |
| 无障碍与资源       | 用途文本通过 `aria-describedby` 关联；展开按钮含 `aria-expanded` 和唯一目标 ID；不新增网络请求、依赖、文件读取或转换器状态。                    |

## 验证

新增排版检查覆盖 5 种语言（含德语英文回退）、明暗主题和 6 个视口：320×640、390×844、800×600、801×600、1366×768、844×390，共 60 组。检查展开前后的边界、列表末尾焦点、搜索/关闭可见性和焦点循环。开发预览与最终生产构建均已通过，页面脚本错误为 0。

最终验证：类型检查 0 错误、0 警告；163 项单元测试通过；变更文件的 Prettier / ESLint、文档链接与 Git 空白检查通过；生产构建成功。`npm run test:browser` 的 11 组回归全部通过，覆盖资源生命周期、本地音频、工作区、输入识别、PDF 输出及引擎重试、格式焦点/分组和图像保真。原有 PDF 回归在展开后继续严格核对全部 23 种格式，并实际转换和验证输出。

截图：[手机常用格式](format-choices/mobile.png)、[桌面常用格式](format-choices/desktop.png)。

真实 iOS/Android 软键盘、安全区、系统大字体和读屏器仍需设备验收。桌面 Chromium 的视口检查不代替这些验证。

复现：先运行 `npm run build`，再运行 `npm run test:browser`（自动启动临时生产预览）；只检查选择器可使用：

```sh
CHROMIUM_PATH=/usr/bin/chromium \
IIPE_TEST_BASE=http://localhost:5174 \
node tests/browser/format-choices.mjs
```

浏览器回归期间不要同时构建或重新生成翻译，否则开发服务器会自动刷新并清空内存队列。
