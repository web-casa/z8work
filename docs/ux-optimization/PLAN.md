日期：2026-09-06。版本：v1.1（经过两轮方案自审与修正）。

状态：第 1、2 批已实施，格式菜单焦点、错误展示和第 3 批剩余的常用格式/用途说明也已补齐。实施、代码审查及验证见 [IMPLEMENTATION.md](IMPLEMENTATION.md)和[格式选择复查](FORMAT_CHOICES.md)；真实移动设备与读屏器验收仍待完成。原始方案内容保留如下。依据是当前工作区已合入的 Pixel Desktop 前端、[本次体验审查](audit/README.md)和现有代码；不以 Git HEAD 代表尚未提交的界面代码。审查依据、修正过程和剩余验证条件见 [REVIEW.md](REVIEW.md)。

2026-09-07 补充：后续独立的[隐私与环保需求](../PRIVACY_AND_ENVIRONMENT.md)已实施，包含移除访问统计、重写隐私页和展示实际结果体积。下方原方案仍是其余体验优化的基线；其中“保留统计配置”和“隐私页已有 HTML lint 问题”的旧状态已被该实现替代。

## 1. 目标和范围

让用户能够迅速完成“添加文件 → 选择格式 → 转换 → 下载”，尤其改善手机、多文件和长文件名场景。保留 ii.Pe 标识、墨绿/奶油白/桃色、方形边框和像素图标；像素字体主要用于品牌和少量装饰，文件名、数值及操作文案使用现有正文文字体系。

| 项目               | 本轮结果                                         | 优先级 |
| ------------------ | ------------------------------------------------ | ------ |
| UX-01 主操作可见性 | 手机固定操作栏；桌面主操作完整可见               | 高     |
| UX-02 文件区密度   | 紧凑文件列表，缩小空状态和重复格式装饰           | 高     |
| UX-03 文件名识别   | 两行文件名、独立扩展名、可展开完整名称           | 高     |
| UX-04 格式选择     | 常用格式、简短用途、全量搜索、明确关闭           | 中     |
| UX-05 转换结果     | 单文件直接下载，展示实际输出格式及体积           | 中     |
| UX-06 状态与恢复   | 部分完成、失败、取消和初始化状态一致，按范围重试 | 中     |

本轮不改品牌方向、不新增转换引擎或依赖、不引入用户账号、服务端存储、转换历史、拖拽排序或虚拟列表。保留已有队列取消修复、语言初始化、ImageMagick 0.0.43、PWA 图标、友情链接、隐私与统计配置。设置、关于、致谢页只验证共享布局的兼容性，不进行全面重设计。

能力提示必须来自实际注册的 `converters`。当前 `getConverters()` 只注册 ImageMagick、FFmpeg、Pandoc；仓库有 `vertd` 文件并不代表它已启用。本轮不注册或恢复视频服务，不因为旧文案提到视频而扩大功能范围；首页、格式菜单、页脚的能力描述同步纠正为当前实际能力。

## 2. 布局与操作规则

### 2.1 桌面与手机

采用一个工作区、一套文件对象和一套动作计算。桌面和手机只改变呈现位置，不能创建两套队列、两套格式选择状态或重复的可聚焦控件。

| 视口         | 布局                                                                     |
| ------------ | ------------------------------------------------------------------------ |
| 大于 1100px  | 左侧紧凑文件列表，右侧约 300–340px 设置/操作区；移除超大且重复的格式名称 |
| 801–1100px   | 压缩间距和右栏宽度，优先保证名称与主操作；不强制大缩略图                 |
| 不大于 800px | 单列文件列表，底部固定“输出格式 + 主操作”；设置保留明确入口              |

将工作区 CSS、菜单形态和现有 `isMobile` 的边界统一为 800px，消除当前 CSS 800px 与脚本 768px 的分歧。它会影响现有手机滚动位置恢复，因此必须复验其他页面往返；不能只改一处数字。

手机保留文档自然滚动，不给文件区再加独立滚动容器。底部操作栏仅在 `/`、`/convert/` 且队列非空时出现；其高度根据真实内容测量，主内容底部留出等高空间及安全区。页尾、最后一个文件和展开内容必须都能滚动到操作栏上方。

桌面右栏在高度足够时随页面保持可见；矮屏或放大后不满足空间时退回自然流，禁止裁掉按钮。手机横屏和系统大字体下允许操作栏换行，不通过缩小文字维持一行。

格式面板/确认对话框打开时，底栏退居背景且不可操作；软键盘出现后搜索框、关闭按钮和结果列表仍位于可视区域，使用可用视口高度处理，不假设 `100vh` 等于键盘上方空间。

### 2.2 空状态和文件列表

- 空状态主上传入口直接可见；保留页头添加入口，但弱化尚不可用的输出区域，移除大面积禁用按钮和 `FORMAT` 装饰。
- 非空队列统一使用紧凑行式展示，本轮不增加网格/列表切换或新的持久化设置。手机缩略图起始尺寸约 48–56px，桌面约 56–64px；文件纸张造型作为小图标保留。
- 每项按“缩略图 / 名称与输入信息 / 状态与结果 / 格式及动作”组织。手机允许动作换到第二行，不能用固定行高裁掉错误或长名称。
- 多文件状态显示数量、完成数与异常数。删除、单项转换和下载保留可访问名称；触屏动作目标以至少 44×44 CSS px 为本项目设计目标，图标本身可以更小。
- 使用现有 `file.blobUrl`，不因列表模式重新生成预览，不提前渲染隐藏菜单里的全部控件。

### 2.3 长文件名

文件名使用正文字体，默认允许两行；扩展名作为独立标识始终保留。正文被省略时提供“查看完整名称”的按钮，点击后在当前行内展开完整名称，再次点击收起；桌面悬停标题仅作补充。

识别与操作仍按 `file.id` 绑定，不能按截断名、显示序号或文件名匹配文件。名称作为纯文本渲染；完整名称能被键盘、触屏和读屏器访问，展开后的焦点留在触发控件。覆盖中文、emoji、无空格长串、多点扩展名和同前缀/同名文件。

## 3. 格式与设置

继续维护现有 `FormatDropdown.svelte`，不另造功能相似的选择器。将类别、搜索、选中项、关闭与焦点恢复保留为同一套逻辑，再调整桌面浮层与手机面板。

- 默认首先展示由当前合法候选集筛选出的常用项，例如图片的 JPEG、PNG、WebP；每项提供短用途说明，其余在“全部格式”中展开。
- 搜索覆盖合法候选的完整集合，不受“全部格式”是否展开限制；保持忽略大小写和扩展名前导点、精确命中优先、无结果反馈。
- 常用配置只负责排序/说明，不能作为新的支持能力清单。候选遵循现有 `FormatInfo` 的输入/输出方向、native 路径、文件大小限制及类别规则；与现有支持关系保持兼容，不借本轮新增跨类别转换能力。
- 批量设置保留当前相同转换器集合的适用条件，并对本次涉及的文件检查候选交集。没有共同候选时明确提示“分别选择格式”，不能对不支持的文件强行设置统一目标。
- JPEG/JPG 等现有别名保持可搜索和可选，不在本轮擅自统一下载扩展名。用途描述不承诺无损、一定变小，或把位图转 SVG 说成矢量描摹。
- 手机提供可见的关闭按钮和背景遮罩；关闭、Escape、选择结果均恢复到实际触发按钮。打开时限制焦点进入背景，关闭后恢复；旋转/跨断点时允许安全关闭菜单，不清空已选格式。
- 搜索框有独立可访问名称，结果数量使用 Paraglide 文案，去掉当前硬编码 `result/results`。每个选择器有唯一标识，不以 `dropdownSize` 作为唯一 ID。
- 打开手机菜单默认聚焦标题或关闭按钮，用户点搜索框时再弹出键盘；桌面打开可直接聚焦搜索。搜索面板高度随键盘调整。

质量、元数据仍使用现有 `Settings.instance`。说明“这些设置在下次转换时生效”；更改设置不自动重转或丢弃已完成结果。更改目标格式只清除目标实际发生变化的文件结果与旧错误，重复选择原格式是无操作；队列运行时禁止修改其目标。

## 4. 结果、状态与动作

### 4.1 真实结果信息

输入体积读取 `file.file.size`；输出体积读取 `file.result.file.size`；实际输出扩展名读取 `file.result.to`，不能读取结果文件名后缀或用户原先选择的 `file.to` 来代替。现有转换器可能实际返回 ZIP。

显示“输入大小 → 输出大小”，输入大于零时再计算体积变化；输出更大时明确写“增加”，不一律用“节省”。零字节输入不显示百分比。展示结果大小不调用 `arrayBuffer()`，不生成第二份 Blob，也不自动解码输出预览。

- 只有一个可下载结果时，主/次下载动作均调用该输入文件现有的 `download()`，文案为“下载 PNG / WebP / ZIP”等实际结果格式。
- 两个及以上结果时调用现有 `files.downloadAll()`，文案标明结果数量和 ZIP；只有部分成功时写“下载已完成的 N 个文件”，不写“下载全部”。
- 保留用户现有命名模板及 ii.Pe 前缀。源转换结果本来就是 ZIP 时，单文件直接下载该 ZIP，不再外包一层。
- 开始下载时对完成结果的文件引用、原名称和实际扩展名取快照，下载的是点击时的结果。`downloadAll()` 保持现有入口，在首个异步读取之前固定该快照，不在异步循环中持续读取可变的全局数组；这不复制文件内容。
- 打包/下载准备期间防止重复触发同一下载动作，失败后恢复可操作状态并显示下载错误；下载完成不清空队列。下载错误属于下载动作，不能设置 `file.failed` 或清空成功结果，也不能被“重试失败项”当作转换失败重新执行。

### 4.2 共享状态和主操作优先顺序

文件卡片、批量操作区、手机底栏和页脚使用同一份派生汇总。现有 `processing`、`queued`、`failed`、`cancelled`、`result` 继续作为事实来源，不重写转换状态机；“不能转换的原因”和“本次转换已失败”分别统计。

运行、排队、完成、失败、取消、未开始是互斥的主状态；阻塞是可执行性的附加属性，不能再与主状态数量相加冒充总数。`processing` 尚未结束时，即使 `cancelled` 已为真也视为“正在取消”，不能立即再次入队；等待现有取消/清理流程结束后才提供继续动作。

下表按从上到下命中，数量均指执行时的实际目标集合。所有状态同时允许查看原因与操作作用范围。

| 条件                                 | 主操作                                  | 其他行为与状态                                                                   |
| ------------------------------------ | --------------------------------------- | -------------------------------------------------------------------------------- |
| 空队列                               | 添加文件                                | 页脚为空闲，不显示“全部完成”                                                     |
| 正在转换/排队                        | 显示“转换中 · 已完成 X/N”，禁止重复提交 | 单项取消继续可用；不阻止它释放队列；无真实进度的转换显示不确定进度，不捏造百分比 |
| 有可执行的未开始文件                 | 转换 N 个文件                           | 如果还存在阻塞项，明确写“转换可用的 N 个文件”；不自动重试失败或恢复已取消项      |
| 无未开始项，有可重试的失败项         | 重试失败的 N 个文件                     | 成功结果保留；暂时不可重试的失败项仍说明阻塞原因                                 |
| 前两类均无，有用户可继续的取消项     | 继续转换 N 个文件                       | 只在用户明确点击后恢复取消项                                                     |
| 已有结果，剩余项不可执行，或全部完成 | 下载已完成结果                          | 一个结果直接下载，多个结果打包；页脚明确“部分完成”或“全部完成”                   |
| 没有结果且全部在初始化/被阻塞        | 显示初始化或具体阻塞原因                | 有对应恢复入口时展示；不显示假的可转换按钮                                       |

只要有成功结果，稳定状态下保留次要下载入口，即便还有待转换或失败项。运行中可保留现有单项下载；批量 ZIP 下载等到队列稳定后启用，避免结果集合在打包中变化。

汇总必须同时包含完成、失败、取消、待转换和阻塞信息；全部成功才能显示“全部完成”。正在运行优先显示总体进度，同时保留失败数；失败后不能退回“准备就绪”。仅在必要的状态切换播报汇总，不让每个进度帧触发整页读屏播报。

### 4.3 执行范围与重试

现有 `convertAll()` 会把所有非运行文件入队，`VertFile.convert()` 会先清空旧结果，因此不能直接用它实现“重试失败项”。

计划对现有方法作一个向后兼容的小扩展：`convertAll(targets: readonly VertFile[] = this.files)`。这是拟新增的可选参数，不是当前已有接口。保留同一个 `batch` 锁、PQueue、并发设置、取消/移除检查，只对去重且仍在队列中的指定对象建立快照和标记。原来的无参数调用语义保留；新界面的首次转换、重试、继续及明确的“重新转换全部”传递各自的目标快照。

目标在入队和开始执行前再次验证；队列运行时新添加的文件不偷偷加入当前批次。取消任务不会因点击其他批量动作自动恢复，删除的对象不能被旧快照复活。显式“重新转换全部”仍是单独动作，并说明它会替换成功结果。

### 4.4 错误原因与恢复边界

当前 `VertFile` 只保留 `failed` 布尔值，错误文本通过 toast 显示后不能稳定恢复。拟增加最小的文件级错误记录，包含分类、说明键和可选纯文本详情；与原有 `failed` 保持一致，并受现有 `conversionVersion` 约束。重试开始、成功、取消及目标变化时按生命周期清理，旧任务的迟到异常不能覆盖新任务。

转换错误分类来自实际发生错误的边界：资源/Worker 初始化、格式不支持、明确可识别的输入问题、转换失败、未知错误。下载错误另存于下载动作的临时状态。Magick/Pandoc 可在已有初始化等待边界附加阶段信息，保留现有 Worker 协议。未识别错误用准确的通用说明，不靠英文字符串猜测“文件损坏”，也不显示底层堆栈作为主要文案。技术详情折叠为纯文本，不写入 HTML、不持久化文件内容或日志。

资源下载失败时，现有转换器没有通用公开的重新初始化接口。本轮不假设存在 `retry()`：允许已就绪引擎重新执行失败文件；需要重载页面才能恢复时明确说明会清空队列，先提供成功结果下载，再经应用内确认执行刷新；转换运行时不刷新。默认不自动刷新、不后台重复上传、不把这次开发缓存问题概括为所有用户的根因。

## 6. 实施批次

1. **共享行为基础**：定义汇总/候选/动作作用范围；加入指定目标的批量执行和有意义的状态测试。此步先解决部分完成与重试语义，供所有呈现共用。
2. **优先体验交付**：紧凑文件列表、名称展开、桌面密度、手机底栏、单文件下载与真实结果体积。同步四种语言和主要视口截图；先评审真实运行效果，再做局部尺寸调整。
3. **选择与恢复完善**：常用格式说明、搜索/面板/焦点、错误记录与总体状态、实际能力文案；完成下载异常、取消、混合文件和键盘场景。
4. **整体验收**：运行下列测试、对照六个审查状态生成新截图、更新改造说明。每批保持可单独检查的差异；不把依赖大升级或旧页面 lint 清理混入本轮。

状态推导和目标选择需新增单元测试，覆盖组合状态、部分完成、取消、输出 ZIP 和零字节等真实边界，不写仅断言 CSS 类名的测试。对队列扩展做集成回归，确认成功项不重转和取消可释放后续任务。

保留现有 8 项 Worker 单元测试，并将本轮关键浏览器步骤整理为可重复的仓库测试脚本；现有临时脚本/历史截图只作参考，不冒充本轮验收。浏览器使用真实小图片和文档夹具；错误场景明确标注故障注入。记录真实下载文件、ZIP 条目/CRC 和截图。

生产构建会生成 Paraglide 消息；新工作区先构建/编译消息，再运行 `bun run check` 和 `bun run test`。检查本轮文件的 ESLint、Prettier、文档链接与 `git diff --check`。隐私页已有的 5 条 `svelte/no-at-html-tags` 应单列现存问题，不能写成全仓库 lint 已通过。

## 8. 完成判定

交付应包含界面代码、四种语言文案、必要测试、六个状态的新旧截图及未覆盖环境说明。当前方案没有需要用户先补充才能开始的业务信息；比例和间距作为上述范围内的实施参数，以真实小屏验证收敛。主要验收项未通过时继续修正，不将未验证项勾为完成。
